## 2. Detailed Breakdown of Each Unwanted File

### 🚨 File 1: `backend/test_scraper_unit.py`
- **What it is**: A 17-line standalone script created during early testing of the portal scraper.
- **Why it is hazardous**:
  ```python
  pdf_bytes = await fetch_attendance_report("[STUDENT_ID]", "[PORTAL_PASSWORD]", headless=True)
  ```
  It had **hardcoded plaintext student credentials** which were identified and deleted.
- **Why it is safe to delete**: It is not imported anywhere in the backend application or used in any tests. The scraper logic is already integrated into `app/scraper.py` and `run_scraper.py`.

---

### ⚠️ File 2: `backend/test_dropdown_selection.py`
- **What it is**: A 200-line scratch script used during development to reverse-engineer SAP WebDynpro DOM dropdowns.
- **Why it causes problems**:
  1. It also contains hardcoded student credentials.
  2. Because its filename starts with `test_`, `pytest` automatically attempts to run it when running `pytest` in `backend/`. Because it defines an `async def test():` function without an async runner plugin, **it causes the pytest suite to fail with an error!** Meanwhile, the real test suite `tests/test_backend.py` passes 47/47 tests.
- **Why it is safe to delete**: The working dropdown selection algorithm was already finalized and incorporated directly into `backend/app/scraper.py`.

---

### 🗑️ File 3: `backend/test_selections_success.png`
- **What it is**: A 76 KB screenshot generated by `test_dropdown_selection.py` line 194 to visually verify that SAP WebDynpro dropdowns were clicked.
- **Why it is safe to delete**: It is an orphaned runtime image artifact with no production use.

---

### 👻 File 4: `frontend/src/components/SubjectGrid.tsx`
- **What it is**: An early component that rendered a responsive CSS grid of `SubjectCard` items.
- **Why it is unused**: During the UI/UX redesign, the dashboard was upgraded to use `IntegratedCoursePanel.tsx` (which supports combined theory/lab tracking, search, and criteria filtering).
- **Proof of non-usage**: Searching `frontend/src/` shows `SubjectGrid` is **not imported anywhere** in `App.tsx`, `Dashboard.tsx`, or any other file.

---

### 👻 File 5: `frontend/src/components/SubjectCard.tsx`
- **What it is**: The old card component representing an individual subject.
- **Why it is unused**: It was only imported by `SubjectGrid.tsx`. Because `SubjectGrid.tsx` is dead, `SubjectCard.tsx` is completely unused. `IntegratedCoursePanel.tsx` renders its own cards with full integration support.

---

### 👻 File 6: `frontend/src/components/AttendanceCriterionTracker.tsx`
- **What it is**: A component created to track subjects meeting or missing the 80% attendance criterion.
- **Why it is unused**: All criteria tracking, tabs (`Safe`, `At Risk`), format filtering, and lecture projections were combined into `IntegratedCoursePanel.tsx`. `AttendanceCriterionTracker.tsx` is not imported anywhere in the codebase.

---

### ℹ️ File 7: `test_data.pdf` (Project root)
- **What it is**: A 271 KB sample NMIMS attendance PDF used during initial parsing development.
- **Status**: Kept for reference. If the user desires a completely pristine workspace, this file can be kept or removed without affecting the application.

---

## 3. How to Clean Up

To delete the unwanted files, you can simply run the following PowerShell command in the project root:

```powershell
# Remove backend scratch tests and artifacts
Remove-Item "backend\test_scraper_unit.py"
Remove-Item "backend\test_dropdown_selection.py"
Remove-Item "backend\test_selections_success.png"

# Remove unused frontend ghost components
Remove-Item "frontend\src\components\SubjectGrid.tsx"
Remove-Item "frontend\src\components\SubjectCard.tsx"
Remove-Item "frontend\src\components\AttendanceCriterionTracker.tsx"
```

After removing these files:
1. `npm run build` in `frontend` continues to pass with 0 errors.
2. `pytest` in `backend` will discover only `tests/test_backend.py` and pass 100% of all tests with 0 failures!
3. All sensitive credentials will be purged from the codebase.
